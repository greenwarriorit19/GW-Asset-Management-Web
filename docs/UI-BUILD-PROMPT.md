# Build prompt — Green Warrior Asset Management & Employee Handover System (current state)

Build a professional, enterprise web application for **Green Warrior Solid Waste Management** that replaces handwritten asset records. It tracks every company asset through its lifecycle — Purchase → Registration → Handover → Transfer → Return → Repair → Loss/Damage → Retirement → Disposal — with a permanent, append-only history. Multi-user, with login, on a shared Supabase (PostgreSQL) database; also runs in a browser-local mode when no database keys are configured.

## 1. Technology
- React 19 + TypeScript + Vite, `react-router` (HashRouter so QR links like `#/assets/GW-AST-MOB-0001` work on static hosting).
- Plain CSS design tokens (no UI framework). Libraries: `qrcode`, `xlsx` (SheetJS), `jspdf`, `html2canvas`, `@supabase/supabase-js`.
- All business rules live in one in-memory store (`Store` class) that persists either to `localStorage` or to Supabase (diff-based writes after every action, Realtime reload on other users' changes). The UI never talks to the database directly.
- Tests: Vitest (business rules + a PGlite run of the SQL schema). Build must pass `tsc`.

## 2. Visual design (strict)
- Palette: deep navy `#0B1F3A` (primary, headers, selected states), navy-700 `#14305A`, navy-100 `#E6EAF1`, charcoal `#2B2F36` (text), cool greys `#3D434C / #5B6470 / #8A93A0 / #C9CFD8 / #DDE1E7 / #F2F4F7 / #F8F9FB`, white. Muted danger `#8B1E2D` on `#F8ECEE`, muted warning `#7A4B00` on `#FBF3E4`. **No green anywhere.**
- Typography: Inter / Segoe UI, 13.5 px base; section headings 12 px uppercase letter-spaced on a light-grey bar; page titles 20 px navy.
- Flat corporate look: white background, 1 px cool-grey borders, thin navy rules under page titles, square corners (no rounded cards), no gradients, no animations, no drop shadows except a faint one under open dropdown/calendar popovers.
- Layout: fixed navy top bar (brand left; on the right a sync badge LIVE / SAVING… / SAVED / NOT SAVED, the signed-in user + role, Sign out). Left sidebar 240 px on light grey with uppercase group labels (Overview, Assets, Custody, Lifecycle, Governance), active item = navy left rule + navy-100 background, numeric navy badges for items awaiting action. Sidebar collapses behind a ☰ button below 820 px; forms drop to one column; A4 documents scale to width.
- Components: metric tiles (label / large navy number / sub-text; red or amber left rule for alerts), horizontal bar lists for breakdowns, data tables (uppercase grey header row with navy bottom rule, zebra-free, row hover, clickable rows, right-aligned numbers, an **Actions** column with Edit / Delete buttons on master-data tables), status chips (uppercase 10.5 px: navy fill for Assigned/Transferred, navy outline for Available, grey for Retired/Disposed, amber for Pending/Under Repair, muted red for Damaged/Lost/Rejected), forms in 2–4 column grids with small grey labels and red asterisks, modals with grey header bar and footer button row, tabs as a thin underline, alerts as left-ruled bars.
- Every dropdown is a **searchable combobox** (type to filter, ↑↓ Enter Esc, × to clear, red border when a required one is empty).
- Every date field is a **calendar picker** (Sun–Sat grid, greyed adjacent-month days, today outlined, selected day navy-filled, month/year selects, ‹ › arrows, Today / Clear footer; shows "15 Sep 2026", accepts typed dd/mm/yyyy).
- All confirmations use an **in-app dialog** (never `window.confirm/prompt`): title, message, mandatory Reason field (min 3 chars, live validation), grey Cancel + red/navy action button, Enter/Esc keys.

## 3. Sign-in & roles
- Login screen (centred navy-ruled card: email, password, Forgot password, Sign in). Users sign in with Supabase Auth; only emails present in the app's Users list can enter.
- Roles are data (built-in + custom): Super Admin (everything), Asset Administrator, Department Head (scoped to own department), Employee (own assets), Auditor/Management (read-only). 31 fine-grained permissions in 5 groups. Users & Permissions page: Users table, Roles table, Role Permission Matrix (✓ / –). Add Role opens a dialog with name, generated code, description and a grouped permission checklist (group "all" toggles, Select all / Clear); Super Admin role is locked; built-in roles can't be deleted; custom roles delete only when unused.
- Add User asks for name, email, role, linked employee, department, Active, and an **initial password** (live "7/8 characters" counter, button disabled until valid) → creates the Supabase Auth login in the same step. Existing users: Create login / Send password reset. Deactivating blocks sign-in.
- Routes are guarded: pages a role can't use are hidden from the menu and blocked by URL.

## 4. Modules (sidebar order)
1. **Dashboard** — tiles: Total Assets (+ purchase value), Available, Assigned, Under Repair, Damaged, Lost, Retired, Disposed, Total Purchase Value, Warranty Expiring (30 days), Awaiting Action; bar lists by Category / Department / Location; Recent Transactions table; Warranty Expiring table. Employees see "Assets assigned to me".
2. **Asset Tracker** — search by Asset ID / serial / IMEI / SIM / name; shows the entire record of one asset: summary tiles, identification, custody chain, handovers, returns, transfers, repairs, incidents, retirement/disposal, documents, full transaction timeline; tab for the A4 Asset History Report; Excel export.
3. **Asset Inventory** — search + filters (status, category, department, location), export Excel, Register Asset / Bulk Import buttons; row click opens the asset.
4. **Asset Registration** — sections Identification (Asset ID auto-preview `GW-AST-<CAT>-0001`, Category, Asset Name, Manufacturer, Model, Serial, IMEI, SIM, Barcode/QR, Ownership Type), Procurement (Invoice No, PO No, Purchase Date, Purchase Cost ₹, Warranty Start/Expiry), Allocation (Status read-only "Available", Condition, Department, Location, custodian read-only "set via handover"), Specification / Accessories / Maintenance Notes / Remarks, attachments (Invoice, Warranty, Photo → uploaded to a Google Drive folder per Asset ID when configured), Reason. Live duplicate warnings for serial/IMEI/SIM. Form resets after save.
5. **Bulk Import (Excel)** — Download template (Assets sheet with 20 columns, mandatory ones marked `*`; Employees sheet; Instructions sheet listing rules and valid codes) → upload → validated preview per row (required fields, duplicates against register and within file, unknown category/department/location, bad dates/values; IMEI mandatory for all rows, SIM mandatory for MOB/TAB/GPS/SIM) → "Import N valid rows" in one atomic batch.
6. **Asset detail** (`/assets/:id`) — action buttons per state (Track, Edit, Issue to Employee, Record Return, Transfer, Send for Repair, Report Loss/Damage, Recommend Retirement); tabs Overview (current state, identification, procurement, QR code with download, photo, purchase documents, custody summary), Transaction History (timeline), Documents, Registration Form (A4), Asset History Report (A4).
7. **Employee Handover** — register with status filter and Employee Clearance Report picker; New Handover: employee (searchable; auto-fills ID, ERP ID, designation, department, DOJ, location, mobile/email), reference `GW-HO-YYYYMM-0001`, issued by, expected return, purpose, location of use, asset table (only Available assets; per-row condition, qty, accessories "Charger - Moto 33W, Back case x2", remarks) → Submit for Approval. Detail page: workflow panel, Department Head approve/reject (comment required), Employee acknowledgement (typed-name signature + checkbox) → status Assigned, then the A4 form.
8. **Asset Return** — record return (assigned asset, condition reported, accessories returned, employee signature, reason) → Under Inspection; register; modal with Inspection (condition, outcome Acceptable→Available / Faulty→Under Repair / Damaged→auto incident) + A4 Return Form.
9. **Asset Transfer** — request (asset, new custodian or department pool, department, location, condition, reason) → Dept Head approval → Asset Admin completes (releases old custodian, generates a fresh handover for the new one) → A4 Transfer Form.
10. **Repair & Maintenance** — open job (asset, fault, vendor, estimated cost, expected return, quotation) → approval → complete (actual cost, completion date, work done, condition, outcome Available / Assigned back to custodian / Retired, service report) → A4 Repair Form.
11. **Lost or Damaged** — report (asset, type, date, reporting employee auto-filled with custodian, location, description, police ref) → Dept Head investigation (notes, responsibility, recovery action/amount, proposed resolution Repair / Recovered / Written Off / Retired) → Management approval applies the resolution → A4 report.
12. **Retirement & Disposal** — recommend retirement (reason, technical recommendation) → management approval → record disposal (method, date, value, vendor, proof file required, data-erasure certificate, data-erased checkbox) → authorization → Disposed, history retained → A4 form.
13. **Reports & Export** — 14 reports (Asset Register, Employee-wise, Department-wise, Location-wise, Available, Assigned, Warranty Expiry, Repair, Lost & Damaged, Return Pending, Retired & Disposed, Transaction History, Asset Value, Audit Log) with filter box, Excel / CSV / PDF export, Print.
14. **Document Management** — upload (asset, linked record type + record, document type, file → Drive, remarks); library with search/filter and Open in Drive / Download.
15. **Audit Log** — every action with user, role, date-time, action code, entity, reason, details; search; Excel export.
16. **Users & Permissions** — see §3.
17. **Master Data & Settings** — tabs Employees (ID, ERP ID, name, designation, department, DOJ, location, mobile, email, Active; Edit/Delete with history-safe blocking), Categories (2–4 letter code → Asset ID format), Departments, Locations, Google Drive (folder ID, OAuth Client ID, Enable, Connect & test, setup steps), Data (JSON backup; in local mode also Restore and Reset).

## 5. Documents (A4, print / PDF / PNG export)
Common frame: company name + system name top-left, document title + Reference No + Document Date + QR (opens the asset) top-right, navy rule; grey section bars; key/value tables; asset tables with each accessory as an indented sub-row (i, ii, …) under the asset; **acknowledgement text and signature row anchored to the bottom of the sheet**; footer "Green Warrior Solid Waste Management — Controlled document; retain per records policy." with reference and generation time. Signature blocks show name, role/designation and date. Documents: Asset Registration, Employee Asset Handover (Employee details incl. ERP ID; Handover details = Reference, Date, Approved By with designation, Approval status; assets issued; acknowledgement paragraph; signatures Employee / Issued By / Authorized Signatory / Approved By), Asset Return (with inspection record), Asset Transfer, Repair & Maintenance, Lost/Damaged Report, Retirement & Disposal Approval, Asset History Report, Employee Clearance Report.

## 6. Business rules the UI must reflect
Unique Asset ID per category; duplicate serial/IMEI/SIM blocked; only Available assets can be issued and they become Reserved while approval is pending; an asset never has two custodians; status becomes Assigned only after the employee signs; returns always go through inspection; damage/loss needs a report, investigation and approval; disposal needs approval plus a proof document; every action records user, date-time and reason; history is never edited or deleted; master data can be deleted only when nothing references it (otherwise deactivate).
